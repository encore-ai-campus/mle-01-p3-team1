# 지역과 주제가 함께 있는 질문의 검색 설계

[Supervisor 흐름도](../architecture/images/supervisor-hybrid-flow-clarified.png)에서 단순한 지역·주제 질문을 Hybrid로 보내는 이유와 구현 범위입니다.

- 기준은 2026-11-14의 연결형 Supervisor CLI입니다. Streamlit 챗봇은 별도 실행 경로입니다.
- 편의시설·개관 요일 조건으로 같은 방식을 넓힌 내용은 [온톨로지 후보 필터](ontology-filter-routing.md)에 있습니다.

## 요약

- **문제:** "경기도 + 자연 관련" 질문이 Graph로 갔다가 두 번 모두 근거 부족으로 보류됐습니다(52.57초).
- **해결:** 지역은 Vector와 BM25 양쪽에 검색 전 필터로 걸고, 주제는 Hybrid의 의미 검색으로 찾습니다.
- **결과:** 답변 성공(55.36초). 최종 근거는 모두 경기도였고, 속도는 빨라지지 않았습니다.

## 문제가 된 질문

> 경기도 권에 있고 자연과 관련된 곳이면 좋겠음

이 질문에는 조건이 두 가지 있고, 둘 다 충족돼야 합니다.
- **경기도:** 정확히 맞아야 하는 지역 조건
- **자연 관련:** 전시나 설명의 의미를 봐야 하는 주제 조건

**이전 실행에서 일어난 일**
- 지역 조건 때문에 Graph를 선택했고, 재시도도 Graph로 진행한 뒤 근거가 없어 보류했습니다. 전체 요청은 52.57초였습니다.
- 두 번째 Graph 검색은 Cypher 생성에만 16.88초가 걸렸습니다.
- 첫 검색은 세부 진단이 남지 않아 정확한 실패 원인을 확정할 수 없습니다.
- Graph 재시도에 이전 실패 피드백이 검색기로 전달되지 않았습니다.
- Neo4j에 자연 관련 자료가 아예 없었다고 결론 내릴 근거는 없습니다.

## 왜 Hybrid를 선택했나

- Neo4j에서도 지역 속성과 본문을 조회할 수 있습니다. 다만 "자연 관련"은 자연사, 동물, 생태처럼 여러 말로 나타납니다.
- Hybrid는 Vector 의미 검색과 BM25 키워드 검색을 함께 쓰고 Cross-Encoder로 재정렬하므로, 이렇게 넓은 주제의 후보를 찾는 데 맞습니다.
- Graph의 Cypher 생성 호출을 거치지 않는 것도 설계상 이점입니다.
- 그렇다고 항상 Neo4j보다 빠르거나 정확하다는 뜻은 아닙니다. 평가로 비교해야 합니다.

## 처리 순서

기본 연결에서 인식 가능한 단순 지역·주제 질문에만 적용합니다.

1. Supervisor가 질문을 정해진 표현과 대조해 Hybrid 경로를 선택합니다.
2. LLM 호출 없이 지역을 추출합니다. 원문 질문은 의미·키워드 검색에 그대로 씁니다.
3. **Chroma Vector와 BM25 양쪽에 같은 시도 필터를 검색 전에 적용합니다.**
4. 두 후보 순위를 RRF로 결합하고 로컬 Cross-Encoder로 재정렬합니다.
5. 검색 결과의 ID와 전체 설명문이 CSV와 일치하면, 설명문 출처와 별도로 가공 CSV의 지역 등 속성 근거를 연결합니다.
6. 답변을 생성하고 인용과 질문 조건을 검증합니다. 근거가 부족하면 재검색하거나 보류합니다.

**근거의 성격**
- 이 경로에서 Hybrid는 Neo4j를 조회하지 않습니다.
- 지역 속성 근거는 일치 검사를 통과한 `museum_final_738.csv`의 가공 행입니다.
- 설명문의 원본 출처가 지역 속성까지 독립적으로 검증했다는 뜻은 아니고, CSV도 사람 검수나 최신성을 보증하지 않습니다.

## Neo4j를 사용하는 질문

- `--with-neo4j`로 연결하면, 지역 관계·요금·운영시간·장소 간 관계처럼 구조화된 조회가 필요한 질문에 Supervisor가 Graph를 선택할 수 있습니다.
- 일부 단순 주변 추천은 좌표로 직선거리를 계산하고 출처를 함께 가져오는 준비된 쿼리를 씁니다. 해당하지 않으면 Text-to-Cypher를 씁니다.
- 위치나 요금 조건이 있다고 항상 Graph를 고르는 것은 아닙니다. 질문 유형, 인식 범위, 연결 여부, 명시적 경로 지정에 따라 달라집니다.
- Graph가 연결되지 않았을 때 Graph 결과를 쓴 것처럼 간주하지 않습니다.
- 한 번의 검색 시도는 하나의 경로만 씁니다. Hybrid와 Graph 결과를 자동으로 합치지 않고, 재검색하면 기존 근거를 새 결과로 대체합니다.

## 적용 범위와 한계

- 자동 Hybrid 경로는 [region_theme.py](../../src/hybrid/region_theme.py)에 정의된 제한된 지역·주제·문장 형태에만 적용합니다. 모든 자연어 표현을 인식하지는 않습니다.
- 무료·유료, 시군구, 주변 거리, 복수 지역 같은 조건이 붙으면 이 패턴으로 처리하지 않고 기존 라우터에 맡깁니다. 기존 라우터의 정확한 선택이나 복합 조건 처리가 보장되지는 않습니다.
- `--route graph` 같은 명시적 경로 지정이 자동 선택보다 우선합니다. 기본 연결이 아닌 사용자 정의 검색기에는 자동 경로가 적용되지 않을 수 있습니다.
- 관련성은 검색·재정렬 뒤 답변 검증에서도 확인합니다. LLM 검증과 출처 연결이 사실 정확성이나 현재 운영 상태를 보장하지는 않습니다.

## 실제 확인과 속도

- **경로:** 같은 질문을 실제 연결 환경에서 한 번 실행했고 `hybrid_search → answer → verify → finish`로 답변했습니다.
- **필터:** 경기도 필터가 적용됐고, Vector와 BM25가 각각 20개 후보를 반환했습니다. 최종 근거의 지역은 모두 경기도였습니다.
- **결과 파일:** [region_theme_check.json](../../outputs/supervisor/region_theme_check.json). `outputs`는 로컬 실행 결과라 다른 환경에는 없을 수 있습니다.
- **시간:** 55.36초로, 이전 52.57초 실패 실행보다 빠르지 않았습니다.
  - Cross-Encoder 23.80초, 답변 생성 8.15초, 검증 11.35초입니다.
  - 두 실행은 처리 경로와 성공 여부가 달라서 이 한 쌍만으로 성능을 비교할 수 없습니다.
  - 여러 질문을 반복 실행해 속도와 검색·답변 정확도를 평가해야 합니다.
