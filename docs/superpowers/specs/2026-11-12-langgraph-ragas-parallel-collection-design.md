# LangGraph Ragas 평가의 GraphRAG 병렬 수집 설계

- 날짜: 2026-11-12
- 대상 브랜치: `codex/project-structure-reorganization`
- 상태: 검토 대기

## 의도

30문항과 300문항 평가에서 질문마다 GraphRAG 검색과 답변 생성을 차례대로 실행하는 시간을 줄이고, 실행 중 현재 단계를 확인할 수 있게 한다. 사용자는 파이썬 명령 하나로 평가를 실행하고, 기존 평가 결과 형식을 그대로 받는다.

## 현재 동작과 범위

`src/evaluation/langgraph/ragas_eval.py`의 `collect_graph_results`가 평가셋의 모든 행을 `app.invoke`로 순차 처리한다. 각 문항은 Neo4j용 Cypher 생성 및 근거 기반 답변 단계를 거치며, 그 후 답변 가능 문항만 Ragas 네 지표로 채점한다.

30문항 평가도 같은 순차 GraphRAG 수집을 거친다. 현재 잠금된 Ragas 0.4.3의 `RunConfig` 기본 `max_workers`는 16이고, 평가 코드는 그 기본값을 사용한다. 따라서 이번 속도 개선의 주 대상은 순차 GraphRAG 수집이며, Ragas 채점 동시성은 바꾸지 않는다.

이번 변경은 GraphRAG 문항 수집만 대상으로 한다. Ragas 점수 계산 방식, 평가셋, Neo4j 데이터, 출력 파일 형식은 바꾸지 않는다.

## 접근 방식

1. **문항별 제한 동시 처리 (선택)**: 최대 8개 질문의 기존 그래프 실행을 동시에 수행한다. 각 작업 스레드는 자기 LangGraph 앱을 한 번 만들어 재사용하고, 완료된 결과는 입력 CSV 순서대로 정렬한다. 진행 건수를 출력하며 `--batch-size`로 동시 요청 수를 조절한다.
2. **질문 여러 개를 한 LLM 요청에 묶기**: 호출 수를 줄일 수 있지만 질문별 Cypher와 근거를 분리하는 프롬프트·응답 처리가 필요하고 현재 그래프 흐름도 크게 바뀐다. 문항별 결과 격리가 중요해 이번 목표에는 선택하지 않는다.

문항별 병렬 처리를 선택한 이유는 현재 검색 및 답변 흐름을 유지하면서 대기 시간을 줄일 수 있기 때문이다. 8개 동시 실행이 기본값이며, API 제한에 걸리면 실행 옵션으로 낮출 수 있다.

## 동작 요구사항

- 기본 동시 실행 수는 8이며, `--batch-size N`으로 바꿀 수 있다. 값은 1 이상이어야 한다.
- 한 스레드에서 실행되는 문항은 같은 LangGraph 앱을 재사용한다. 스레드 간에는 앱을 공유하지 않는다. `Neo4jText2Cypher`가 최근 Cypher 상태를 객체에 보관하므로 공유하면 문항 간 상태가 섞일 수 있다.
- Neo4j 드라이버는 현재 수집 함수 호출 동안 공유한다. Neo4j Python 드라이버의 스레드 안전 세션 생성을 활용하고, 각 그래프 요청은 자체 쿼리 실행을 한다.
- 결과의 순서와 각 결과의 `question_id`는 평가셋 입력 순서를 보존한다.
- 평가 시작 시 전체 문항 수, 동시 실행 수와 GraphRAG 수집 시작을 표시한다. GraphRAG 문항이 끝날 때마다 완료/전체 수와 해당 `question_id`를 표시한다.
- Ragas 채점 직전에 채점 문항 수를 표시하고 `show_progress=True`로 진행 막대를 보여준다. Ragas 0.4.3의 기본값도 `True`지만, 진행 표시가 실행 설정에 묻히지 않도록 명시한다.
- GraphRAG 또는 Ragas 단계가 끝나면 완료 문구를 표시한다. GraphRAG 실패 시 기존처럼 실패한 `question_id`를 포함해 오류를 보고하고 평가를 중단한다.
- Ragas 채점과 기존 CSV/JSON/Markdown 결과물은 계속 동일하게 실행한다.
- 실행 문서에 동시성 옵션과 API rate limit 발생 시 낮추는 방법을 적는다.

## 제한사항

- 동시 요청으로 GraphRAG의 API 처리량은 높아질 수 있지만 실제 소요 시간은 OpenAI/Neo4j 응답 속도와 rate limit에 좌우된다.
- Ragas 채점 단계의 동시성은 이번 범위가 아니다.
- GraphRAG의 최대 동시 OpenAI 요청 수는 `--batch-size` 값에 따라 증가하며, 기본값 8은 실행 환경에 따라 낮출 수 있다.

## 구현자가 정할 세부사항

스레드별 앱 생성 시 설정 전달 방식과 진행 로그의 문구는 현재 함수 구조에 맞춰 정한다. 기존 외부 실행 명령은 기본값만으로 동작해야 한다.
