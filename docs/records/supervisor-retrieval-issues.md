## 지역과 전시 주제가 함께 있는 질문 (2026-11-14)

설계 이유와 측정 수치는 [지역·주제 검색 설계](../decisions/region-theme-routing.md)에 있습니다. 여기에는 문제 해결 관점만 적습니다.

- **증상:** `경기도 권에 있고 자연과 관련된 곳이면 좋겠음`이 지역 조건 때문에 Graph로 갔고, 두 번 검색한 뒤 근거 부족으로 보류됐습니다.
- **원인:**
  - Graph가 실패해도 재시도에서 다시 Graph를 골랐고, 재시도 피드백이 Graph 검색기로 전달되지 않았습니다.
  - Hybrid는 Chroma와 BM25에 공통 메타데이터 필터를 적용할 수 있었지만, LLM 질문 분석이 꺼져 있으면 필터가 자동으로 만들어지지 않았습니다.
  - Neo4j 설명문에는 자연 관련 자료가 있으므로, 데이터가 아예 없어서 생긴 문제로 볼 수는 없습니다.
- **해결:**
  - 해석이 명확한 단순 `지역 + 주제` 질문은 Hybrid로 보냅니다.
  - LLM 호출 없이 시도를 추출해 Chroma와 BM25 양쪽에 검색 전에 적용합니다. RRF, Cross-Encoder, 출처 검사, 답변 검증은 그대로입니다.
  - 지원 패턴은 `src/hybrid/region_theme.py`에 한정합니다. 무료·유료, 시군구, 주변 거리, 복수 지역 같은 조건은 이 경로에서 빼서 기존 라우터에 맡기고, 명시적으로 지정한 route는 유지합니다.
  - Neo4j와 Chroma DB는 바꾸지 않았습니다.
- **결과:** 답변에 성공했고 최종 근거는 모두 경기도였습니다. 속도는 개선됐다고 볼 수 없어 재정렬과 LLM 호출 시간을 따로 줄여야 합니다.

## 주변 추천의 출처·거리 누락 (2026-11-14)

- **증상:** 부산 서구 주변 추천이 Graph 경로를 고르는 데는 성공했지만 근거가 부족했습니다.
  - 첫 시도에서는 같은 구라는 사실만으로는 가까운지 확인할 수 없었습니다.
  - 재시도에서는 출처 정보가 빈 결과가 돌아왔습니다.
- **확인:** 실제 Neo4j에서 두 장소의 좌표와 `HAS_SOURCE` 문서 연결이 있는 것을 확인했습니다.
- **해결:** 일부 단순 지역 주변 추천에 대해, 등록된 좌표로 직선거리 5km 이내 후보를 찾고 각 장소의 출처를 함께 돌려주는 읽기 전용 쿼리를 추가했습니다.
- **주의:**
  - 직선거리는 도보 거리가 아닙니다.
  - 같은 좌표는 기록된 좌표가 같다는 뜻일 뿐입니다.
  - 조건이 복잡한 질문은 이 쿼리의 적용 범위 밖입니다.

## 속도 계측 (2026-11-14)

- `--timings`는 가드레일, 라우팅, 검색, 답변, 검증 시간을 시도별로 보여 줍니다.
- Graph는 Cypher 생성과 Neo4j 조회를, Hybrid는 Cross-Encoder 로딩과 추론을 따로 표시합니다.
- 검색 세부 시간은 검색 전체 시간에 포함되고, 병렬 검색 시간은 서로 겹칩니다.
- `--out`을 쓰면 전체 요청 시간과 시도별 trace가 JSON으로 저장됩니다.

```powershell
.\.venv\Scripts\python.exe -m src.agent.supervisor.run --team-hybrid --with-neo4j --interactive --timings
```

## 온톨로지 v2 연결 후 근거 전달 점검 (2026-11-14)

온톨로지 후보 필터와 Neo4j v2를 연결한 뒤, 경로별로 실제 질문을 실행했습니다. **검색 → 답변 → 검증**까지 근거가 끊기지 않고 전달되는지를 확인했고, 빠진 곳 3군데를 채웠습니다. 설계 배경은 [온톨로지 후보 필터](../decisions/ontology-filter-routing.md)와 [온톨로지 v2](../architecture/ontology-v2.md)를 참고하세요.

### 1. 필터가 고른 편의시설 근거를 검증 단계가 인정하지 않음

- **증상:** `경기도에 주차 가능하고 카페 있는 자연 관련 박물관`이 두 번 검색한 끝에 보류됐습니다(55.42초). 필터는 주차장·카페 기록이 있는 후보 3곳을 정확히 골랐지만, Verifier는 "편의시설 기록이 메타데이터 출처로 검증되지 않았다"고 거부했습니다.
- **원인:** Verifier는 `metadata_provenance.fields`에 들어 있는 CSV 필드만 기록된 값으로 인정합니다. 이 목록(`provenance.py`의 `METADATA_FIELDS`)에 `closure_rule_raw`는 있었지만 **`amenities_raw`가 없었습니다.**
- **해결:**
  - `METADATA_FIELDS`에 `amenities_raw`를 추가했습니다.
  - `structured_match` 문구가 "CSV amenities_raw의 '카페테리아' 항목"처럼 근거로 쓴 필드와 원문 항목을 밝히도록 바꿨습니다.
  - Answer/Verifier 프롬프트에 규칙을 넣었습니다. 출처 필드에 있는 원문 항목은 기록된 값으로 인정하고, `카페테리아`→카페, `주자장`→주차장 같은 매핑은 지역 별칭처럼 애플리케이션 규칙으로 받아들입니다. 수량과 실시간 상태는 여전히 답하지 않습니다.
- **결과:** 재시도 없이 한 번에 답변했습니다(40.73초). 전곡선사박물관과 닻미술관을 근거와 함께 제시했고, "자연 관련"에 맞지 않는 후보 1곳은 답변 단계에서 제외됐습니다.
- **같은 원인 확인:** 개관 요일 조건(`월요일에도 여는 경기도 박물관 중 주차 가능한 곳`)도 같은 경로로 답변했습니다(33.82초).

### 2. 조건을 만족하는 기록이 없을 때 같은 검색을 반복하고 이유를 말하지 않음

- **증상:** 필터 후보가 0개면 근거 없음 → 검증 실패 → **같은 검색 재시도** → "근거 부족" 일반 메시지로 끝났습니다. 조건과 데이터가 같아서 재시도 결과도 항상 같은데, 시간만 쓰고 사용자는 이유를 알 수 없었습니다.
- **해결:**
  - Hybrid 진단의 `ontology_filter.status == "empty"`를 Supervisor가 `no_record_reason`으로 받습니다.
  - 이 값이 있으면 재시도 없이 바로 보류하고, 보류 메시지에 어떤 조건의 기록이 없었는지와 "기록이 없다고 실제로 없다는 뜻은 아님"을 함께 안내합니다.
  - 다른 이유로 실패한 경우에는 지금처럼 재시도합니다.
- **결과:** `주말에 문 여는 서울 박물관 중 휠체어 대여 되는 곳`이 8.46초 만에 "기록된 데이터에서 조건(서울특별시, 편의시설 휠체어 대여·이용, 토일요일 개관)을 모두 만족하는 시설을 찾지 못했습니다…"로 끝났습니다. LLM 답변·검증 호출은 0회입니다.

### 3. 기관 질문에서 기준 시설의 연결 근거가 없음

- **증상:** `창녕박물관과 같은 기관이 운영하는 다른 시설은?`이 Graph 고정 쿼리로 박진전쟁기념관을 찾았는데도 두 번 보류됐습니다(28.50초).
- **원인:**
  - 결과 행에는 후보 시설의 운영기관만 있고, 기준 시설(창녕박물관)이 그 기관과 연결된 근거가 따로 없었습니다.
  - 두 시설의 원문 표기도 `경상남도 창녕군`과 `경상남도 창녕군청`으로 달라서, Verifier가 같은 기관으로 인정하지 않았습니다.
- **해결:**
  - 지역 비교 질문과 같은 방식으로, 기준 시설의 `OPERATED_BY`/`MANAGED_BY` 연결을 별도 근거(`evidence_role=anchor`)로 붙입니다.
  - 결과 행에 `org_key`를 넣었습니다.
  - 프롬프트에 규칙을 넣었습니다. 원문 표기가 달라도 같은 Organization 노드면 같은 기관(규칙 정규화)으로 보고, 관리기관은 UNVERIFIED로 표시합니다.
- **결과:** 재시도 없이 답변했습니다(12.96초). Neo4j 조회 2회이고 LLM Cypher 생성은 0회입니다.

### 함께 확인한 것

| 경로 | 질문 | 결과 |
|---|---|---|
| Graph, LLM이 v2 Cypher 생성 | `경상남도 창녕군이 운영기관으로 기록된 시설은 어디야?` | 답변 성공(20.73초, Cypher 생성 9.48초) |

후보 필터와 Neo4j 후보가 일치하는지 점검한 결과는 [온톨로지 후보 필터](../decisions/ontology-filter-routing.md#한계와-다음-단계)에 있습니다.

### 남은 과제

- **관리기관 고정 쿼리(`same_manager`):** 단위 테스트와 실제 DB 조회만 확인했고, Supervisor 전체 흐름은 실행하지 않았습니다.
- **`--with-vector`로 Vector 경로를 직접 고른 경우:** 후보 필터를 거치지 않습니다. 기본 연결에서는 구조 조건 질문이 Hybrid로 고정되므로 해당되지 않습니다.
- **평가셋:** 구조 조건·기관 질문 평가셋이 없어, 한 번씩 실행한 결과 이상의 정확도는 아직 말할 수 없습니다.

### 1. Q252: 검색은 맞았는데 재정렬이 밀어냄

- **근거:** 「충청남도 시도민속문화재 32호에 해당하는 유물은?」의 정답(보령문화의전당)은 BM25 1위, Vector 7위, RRF 2위였습니다. 그런데 Cross-Encoder를 거치자 상위 5위 밖으로 밀렸습니다. 최종 후보들의 재정렬 점수는 0.002~0.008로 모두 0에 가까웠어요.
- **원인:** 번호로만 찾는 질문이라 의미 기반 재정렬이 확신 없이 순서를 뒤집었습니다. 그 노이즈가 RRF의 좋은 순서를 덮어썼어요.
- **해결:** `HYBRID_RERANK_MIN_CONFIDENCE`(기본 0.1). 재정렬 최고 점수가 이 값보다 낮으면 재정렬 순서를 쓰지 않고 RRF 순서를 유지합니다.
- **왜 0.1인가:** 기준선 144문항 중 최고 재정렬 점수가 0.1 미만인 문항은 Q252 하나뿐이었습니다(0.0081). 그다음으로 낮은 Q183이 0.2243이라, 다른 문항의 순서는 바뀌지 않습니다.
- **결과:** Q252가 정답으로 답변됐습니다(Hit@5 1.0, Faithfulness 1.0).

### 2. Q183: 질문에 박물관 이름이 있는데도 못 찾음

- **근거:** 「소수박물관 제2전시실의 주제와 주요 전시물은?」의 정답은 Vector 20위 밖, BM25 16위였고, RRF 후보 20개에 들지 못해 재정렬 전에 탈락했습니다. 답변은 "소수박물관 정보가 없어 확인할 수 없다"였어요.
- **원인:** "소수"가 일반 단어라 이름의 변별력이 약했습니다. Vector는 이름이 비슷한 소전미술관을 가져왔어요.
- **해결:** `src/hybrid/name_match.py`. 질문에 CSV에 기록된 시설명이 그대로 적혀 있으면 그 시설을 재정렬 후보 맨 앞에 넣습니다. 최종 순서는 여전히 재정렬이 정합니다.
  - 공백과 괄호 계절 표기는 무시하고, 가장 긴 이름만 인정합니다(「서대문자연사박물관 수유실」에서 「박물관 수」가 따로 잡히지 않음).
  - 4글자 미만 이름(예: 「바움」)은 일반 단어와 겹쳐 제외합니다.
  - 온톨로지 후보 필터가 걸린 질문에서는 후보 밖의 시설을 넣지 않습니다.
  - `HYBRID_NAME_MATCH=off`로 끌 수 있습니다.
- **근거 확인:** v1 150문항 중 126문항에서 이름이 일치했고, 그중 120문항은 정답 시설과 같았습니다. 나머지 6문항은 보류가 기대 동작인 질문(「박진전쟁기념관이 오늘 임시 휴관하는지」 등)이라 후보에 들어가도 답변은 보류됩니다.
- **결과:** Q183이 정답으로 답변됐습니다(Hit@5 1.0, Faithfulness 1.0).

### 3. 묻지 않은 정보의 부재를 덧붙임

- **근거:** 기준선에서 Q001, Q267 등 5문항은 답이 맞는데도 Faithfulness가 0.5였습니다. 답변 끝에 "구체적인 행사명은 자료에 나와 있지 않습니다" 같은 문장을 덧붙인 것이 원인으로 보입니다. 채점기가 이 문장을 근거 없는 주장으로 봤어요.
- **해결:** 평가용 답변 프롬프트와 Supervisor 답변 프롬프트에 "질문이 묻지 않은 세부 정보(정확한 이름·일정·개수)가 자료에 없다는 말은 덧붙이지 않는다"를 추가했습니다.
- **결과:** 같은 문항(v1 Hybrid 113개)의 Faithfulness는 기준선 0.961, 이번 0.960으로 거의 같습니다. 효과가 뚜렷하지 않아요. 문항별로 확인한 것이 아니라 평균만 비교했고, 이번 평가는 라우팅 변화와 섞여 있어서 이 수정만의 효과는 분리하지 못했습니다.

### 4. Ragas 판정 오류 (0점·누락)

- **근거:** 기준선 Q018, Q022, Q204는 답이 정확하고 문맥과 거의 같은 문장인데도 Faithfulness가 0이었고, Q134는 채점 자체가 실패했습니다.
- **해결:** Faithfulness가 0이거나 비어 있는 문항만 캐시 없이 한 번 더 채점합니다. 누락이면 새 값을 쓰고, 0이면 두 값의 평균을 씁니다. 다시 채점한 문항은 `per_question.csv`의 `ragas_faithfulness_rescored`에 표시합니다.
- **결과:** 이번 평가에서 37문항이 다시 채점됐습니다. v2 새 문항에서 Faithfulness 0이 많았기 때문이에요(7번 참고).
- **한계:** 진짜 0점일 수도 있어서 평균으로 완화했을 뿐입니다. 점수 신뢰도가 정확히 얼마나 올랐는지는 판단하지 못했습니다.

### 5. 라우터가 설명형 질문을 Graph로 보냄

- **근거:** 첫 v2 평가에서 v1 27문항이 Graph로 갔고, 그중 17문항이 보류됐습니다(이 중 3문항은 보류가 정답인 질문). 답변 가능 문항으로 비교하면 Graph 경로는 Hit@5 0.674·Faithfulness 0.297, Hybrid 경로는 Hit@5 0.941·Faithfulness 0.818이었습니다. Graph로 간 질문은 「제주 서귀포에서 항공기 26대와 우주 전시…」, 「판교박물관은 몇 년에 개관했나요?」 같은 설명형이었습니다.
- **원인:** 라우터 프롬프트에 "필수 지역은 정확한 조건이라 Graph를 우선한다"와 "요금·개관시간·지역·주소는 설명 질문이어도 Graph"라는 지시가 있었습니다. 게다가 Graph가 실패하면 재시도도 Graph였습니다. 기준선은 경로를 Hybrid로 고정해서 이 문제가 드러나지 않았습니다.
- **해결:**
  - 라우터 프롬프트를 고쳤습니다. 설명으로 답하는 질문은 지역이 있어도 Hybrid, 레코드를 가로지르는 구조가 필요한 질문(같은 시군구·같은 기관, 두 시설의 지역 비교, 직선거리 주변, 인용문의 출처)만 Graph로 보냅니다.
  - 준비된 Graph 쿼리가 있는 질문은 LLM 라우터를 거치지 않고 바로 Graph로 보냅니다.
  - Graph가 근거를 못 찾으면 재시도는 Hybrid로 합니다. Graph가 근거를 찾았고 부족한 것이 요금 같은 구조 정보일 때만 Graph를 다시 시도합니다.
- **상태:** 단위 테스트로 라우팅 동작을 확인했습니다. 기존 Neo4j 10문항은 모두 준비된 쿼리로 처리되는 것도 확인했어요. 전체 효과는 다시 평가해야 알 수 있습니다.

### 6. 가드레일 동시 초기화 실패

- **근거:** Q001~Q007 7문항이 검색은 성공했는데 "안전 검사를 할 수 없어 답변을 드리기 어려워요"로 끝났습니다. 평가는 8문항씩 동시에 처리하는데, 이 문항들이 첫 묶음이었습니다. 이후 문항에서는 같은 오류가 없었어요. V2-SF12 1문항은 출력 가드레일이 답변을 부적절하다고 차단한 오탐입니다.
- **원인:** 시작 직후 동시에 들어온 검사가 NeMo 초기화와 겹쳐 시간 초과된 것으로 보입니다. 직접 재현하지는 않았습니다.
- **해결:** 검사가 실패하면 한 번 더 시도하고(`guard.py`), 평가는 시작 전에 가드레일을 한 번 초기화해 둡니다.
- **상태:** 재시도 동작은 단위 테스트로 확인했습니다. 출력 가드레일 오탐(V2-SF12)은 이번 수정으로 해결되지 않습니다.

### 7. Ragas가 편의시설·휴관 근거를 못 봄

- **근거:** v2 새 문항 46개의 Faithfulness는 0.211, Context Recall은 0.039였습니다. 그런데 새 흐름은 의도대로 동작했어요(기관 질문 14개 중 13개 답변, 기록 없음 5개와 개수·실시간 3개는 모두 보류).
- **원인:** 편의시설·휴관 근거는 `metadata`(출처 연결 필드, `structured_match`)에 들어 있는데, Ragas는 본문(`text`)만 문맥으로 받습니다. 답변이 맞아도 근거가 없어 보였어요. 기관 질문은 맨 앞에 붙는 기준 시설(anchor) 근거 때문에 Hit@1도 낮게 나왔습니다.
- **해결:** 채점 문맥에 구조화 근거를 넣습니다(`ragas_context`). 순위 지표에서는 `evidence_role=anchor`인 항목을 후보에서 제외합니다.
- **상태:** 단위 테스트로 확인했습니다. 재평가가 필요합니다.

### 8. Q024가 오류로 집계됨

- **근거:** 「제주에서 조천만세·법정사·해녀 항일운동을 함께 다루는 기념관은?」이 첫 평가에서 오류(`ValueError`)로 기록됐습니다. 같은 질문을 Graph로 직접 실행하면 오류 없이 결과 0건으로 끝납니다. 오류를 재현하지 못했어요.
- **원인 판단:** Graph 시도에서 오류가 났더라도 재시도가 끝난 최종 결과와 무관하게 오류로 센 집계 방식이 문제였습니다. 실제 오류가 났던 시점의 세부 내용은 남아 있지 않습니다.
- **해결:** 최종 시도가 검증 통과면 오류로 세지 않고, 근거를 얻은 경우는 검색 오류로 세지 않습니다.
- **상태:** 단위 테스트로 확인했습니다.
