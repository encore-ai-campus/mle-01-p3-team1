### MH002 — 평가가 중단됨
- **증상:** 이전 실행이 MH002에서 `NameError: name 'region' is not defined`로 중단됐습니다.
- **수정:** [Neo4j 결과 변환 코드](../../src/agent/neo4j_text2cypher.py)가 선언되지 않은 `region` 변수를 조건으로 참조하던 부분을 실제 쿼리 템플릿 이름 검사로 바꿨습니다.
- **결과:** 4차 `summary.json`에 질문 10개가 모두 처리된 것으로 기록됐습니다.

### MH001 — 같은 지역 시설의 근거 누락
- **증상:** 정답 ID는 검색됐지만 Context Recall이 0.667이었습니다. 검색 출처 ID는 비교 대상인 M0001 쪽만 기록됐습니다.
- **원인 판단:** 후보를 찾은 사실만으로는 같은 시군구 관계와 다중 홉 경로가 평가 문맥에 명확히 전달되지 않은 것으로 보입니다. 당시 Cypher가 저장되지 않아 누락된 세부 조건은 확정할 수 없습니다.
- **수정:**
  - [같은 시군구 시설 쿼리](../../src/agent/neo4j_text2cypher.py)가 anchor와 candidate의 지역을 함께 반환합니다.
  - 실제 사용한 `LOCATED_IN` 경로를 `graph_path`로, 후보의 `HAS_SOURCE` 문서도 함께 반환합니다.
  - [Ragas 문맥 구성](../../src/evaluation/langgraph/ragas_eval.py)이 이 구조화 필드를 문맥에 포함합니다.
- **결과:** 3·4차 모두 M0003을 검색했습니다. 3차에는 anchor M0001의 출처만 기록됐지만, 4차에는 후보 M0003의 `DOC-B0003-TOUR_API-130107`도 포함됐고 Context Recall이 0.667에서 1.000으로 올랐습니다.

### MH010 — 인용 출처의 구간
- **증상:**
  - 1차에는 출처 답변이 있었지만 Context Recall이 0이었고, 2차에는 0.333까지 올랐습니다.
  - 3차에는 문서 ID는 맞았지만 span ID가 `M0710:000`뿐이었습니다.
  - 질문의 인용 구간은 `M0710:001`이고, 같은 출처의 다른 구간은 `M0710:000`입니다.
- **원인 판단:** 이전 Ragas 문맥 구성기는 `matched_span_text`와 `related_span_text`를 제외했습니다. 그래서 검색 결과에 같은 출처의 다른 구간이 있어도, 인용 seed 구간이 Ragas에 전달되지 않을 수 있었습니다.
- **수정:**
  - [인용문 출처 쿼리](../../src/agent/neo4j_text2cypher.py)가 인용문과 일치하는 seed span과, 같은 박물관·같은 출처의 sibling span을 함께 반환합니다.
  - Ragas 문맥 구성기가 `matched_span_*`와 `related_span_*`를 포함합니다.
- **결과:** `retrieved_span_ids`가 3차 `M0710:000`에서 4차 `M0710:000;M0710:001`로 늘었고, Context Recall은 0에서 0.500으로 올랐습니다.
- **남은 일:** 두 구간을 찾았는데도 점수가 절반이라, 기준 답변의 어떤 근거가 문맥에 빠졌는지 정답 문장과 실제 Ragas 문맥을 대조해야 합니다.

### MH004 — 정답 후보 누락 (미해결)
- **증상:** 1차에는 M0468을 찾지 못했고, 2차에는 찾았습니다. 그런데 3·4차에는 앵커 M0466만 반환했고, 정답 박물관 ID recall과 Context Recall이 모두 0입니다.
- **원인 판단:**
  - 정답 후보 자체가 결과에 없으므로 답변 생성 전 단계인 후보 검색과 쿼리 조건부터 확인해야 합니다.
  - 질문의 `갖췄다고`와 본문의 `갖추고` 형태 차이가 영향을 줬을 수 있습니다.
  - `top-k`가 10에서 5로 바뀌어 실행 간 직접 비교에는 한계가 있습니다.
- **수정:**
  - 같은 지역 후보의 span을 조건과 대조하는 템플릿을 추가했습니다.
  - `갖췄`를 `갖추`로 정규화하고, 템플릿 결과가 없으면 기존 Text-to-Cypher로 재시도합니다.
- **결과:** 4차에서도 M0468이 검색되지 않았습니다. 검색 쿼리와 후보 조건을 따로 분석해야 합니다.

### MH006 — 정밀도 하락
- **확인 방법:** 검색 결과와 Ragas reference가 맞는지 문항별 CSV에서 비교했습니다.
- **결과:** 4차에 retrieved ID `M0012;M0010` 중 정답은 M0010 하나였습니다. Context Recall은 1.0이지만 Context Precision은 0.500이었습니다.
- **판단:** 불필요한 후보가 포함됐을 가능성이 있습니다. 후보 필터를 추가한다면 Recall이 떨어지지 않는지 함께 확인해야 합니다.

### 일괄 조치를 하지 않은 이유
4차에서 MH001·MH002·MH003·MH005·MH006·MH007·MH008·MH009는 Context Recall이 1.0이었습니다. 이 문항들까지 검색 범위를 넓히면 이미 높은 Faithfulness와 Context Precision이 떨어질 수 있어, 일반적인 `top-k` 증가는 적용하지 않았습니다.

## Faithfulness가 실행마다 달라진 이유

- **수치:**
  - Faithfulness는 1차 0.2624, 2차 0.9639, 3차 0.9385, 4차 0.9778입니다.
  - 4차 문항별 Faithfulness는 대부분 1.0이고, MH006만 0.778입니다.
- **판단:**
  - 네 실행 사이에 코드와 `top-k`가 바뀌었고 답변·judge 모델의 생성 결과도 달라질 수 있어, 코드 변경 때문이라고 단정할 수 없습니다.
  - Context Precision이 2·3차 거의 1.0, 4차 0.95라서, 무관한 문맥이 대량으로 들어온 것이 주원인이라고 보기는 어렵습니다.
  - 일부 답변이 근거를 넘어섰거나 judge 판정이 달라졌을 가능성은 있습니다.
- **한계:** 문항별 judge 사유가 저장되지 않아, 어떤 문장이 점수를 낮췄는지는 현재 자료로 확인할 수 없습니다.
- **다음 실행에서:**
  - Faithfulness가 낮은 문항은 답변과 실제 retrieved context를 함께 비교합니다.
  - Precision이 높은 지금 상황에서는 Recall을 올리려고 검색어를 OR로 바꾸거나 `top-k`를 늘리지 않습니다.
